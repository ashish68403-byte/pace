# Results

The numbers the write-up quotes. Each file here comes from one command, records the corpus commit
and the exact git commands behind it, and re-running that command on the same corpus and graph
reproduces it byte for byte.

| File | Command | What it measures |
|---|---|---|
| `history_truncation.json` | `uv run pace measure truncation` | For every in-scope file: its history by today's path, rename-aware, and by `git log --follow` |
| `pool_census.json` | `uv run pace measure pool` | The benchmark's pool: commit-message documents and PR links (B2), then the GitHub fetch — PR documents per kind, the request cost, and B2's links checked against GitHub's merge commits (B4) |
| `golden_census.json` | `uv run pace golden generate` | The golden set's census: candidates per rule, leakage-filter outcomes per template, the split, dropped examples. Its records are `provenance/eval/golden/auto_full.jsonl` |
| `leakage_verdict.json` | `uv run pace leakage --from-db --no-dense --golden provenance/eval/golden/auto_full.jsonl --json-out results/leakage_verdict.json` | Checkpoint B's leakage verdict on the dev split (ADR-0003 §6): every lexical baseline with its Wilson interval, before and after the filters |
| `github_manifest.jsonl` | `uv run pace github backfill` | One line per fetched PR description and comment: kind, PR number, comment id and the SHA-256 of the stored text. No text, no logins (DATA-PROTECTION.md §3) |
| `gold_validity_audit.json` | `uv run pace audit report` | ADR-0004's gold-validity audit: the dev set's validity rate from 56 stratified, labelled records with its interval; what PR text adds over the commit message; self-agreement once the 15-record re-label is in; reachability at k = 100; linked against unlinked commits. Its inputs are `provenance/eval/audit/` |
| `ablation.json` | `uv run pace eval ablation` | Checkpoint B's ablation table on the retained dev split (slices B5a and B5b), six rows: grep, the probe's identifier-aware BM25 (the reference), the production BM25 index before and after its identifier fix, exact dense retrieval, and their RRF at the spec's fixed k = 60. Each has recall@10, MRR@10 and nDCG@10 with intervals, by query class and by symbol df; every row against the reference, and three named pairs, carry D, the MDE and the difference divided by the gold's validity (ADR-0004 §8); the fused row's k sweep is sensitivity only. Refuses to write unless the verdict, the stored vectors and the question vectors all check out. Run it on a clean BM25 index (`VACUUM chunks`, then `REINDEX INDEX chunks_bm25_idx`): the table records the index's state |
| `ablation_per_query.jsonl` | `uv run pace eval ablation` | One line per scored record: its query class, its symbol df, and each row's first gold rank. Every number in `ablation.json` can be recomputed from it |
| `lineage.json` | `uv run pace measure lineage`, after `uv run pace lineage build` and `uv run pace blame build` | Slice C3a's lineage of Airflow's in-scope functions: identities and versions by stage, ambiguous cases and refused revisions; the identity-break rate among the functions alive at the pinned commit, with and without the 2025 move, with Wilson intervals; arm C's size per question function; and PREREGISTRATION.md's agreement check with `git log -L` on its fixed 100-function sample, with a labelled, not-pre-registered breakdown of the disagreements. It scores nothing against gold |
| `oracle.json` | `uv run pace eval oracle` | Slice C3b's single run of claim 3 on CodeShovel's 40 Python oracle functions: each function's oracle commits (a side-branch label at its merge), lineage's and `git log -L`'s, with precision, recall and F1; each arm's means, the 16 rename-or-move and the 5 nested-or-property functions apart; and claim 3's paired difference, interval and verdict in the pre-registered words. It records the code's commit and the pre-registration's, and refuses to run on modified code |
| `provenance.json` | `uv run pace eval provenance` | Slice C4's single run of claims 1 and 2 on the 4,206 retained dev questions: each arm's recall (A blame, B the equal-size control, C lineage, L `git log -L`, and unfiltered blame, labelled), overall and by query class; every paired difference with its interval, D, the MDE and the difference divided by the gold's validity; claim 1's verdict and claim 2's reading in the pre-registered words; the split C − A = (C − B) + (B − A); the cross-check against the censuses; and the agreement check's qualification. It refuses to run on modified code |
| `provenance_per_question.jsonl` | `uv run pace eval provenance` | One line per question: its qid, query class, function, gold commit, arm sizes and each arm's value. Every number in `provenance.json` can be recomputed from it. No question or commit text |
| `blame_arms.json` | `uv run pace measure blame`, after `uv run pace blame build` | Slice C2's blame arms for the 1,777 functions the retained dev questions name: the commands that made the stored rows; trap 3 on their lines, with and without the mechanical list; how many commits arm A, unfiltered blame and arm L hold per function; and whether the 2025 move stops blame or `git log -L`. It scores nothing against gold: that is slice C4's |
| `pool_embedding.json` | `uv run pace pool embed` | The pool's document vectors, described: the model, its file's SHA-256 and fastembed's version; documents and 512-token truncations per kind; one fingerprint over every vector. The vectors stay in pace-db (DATA-PROTECTION.md §3), and `pace eval ablation` refuses vectors this file does not describe |

`artifacts/` is different: gitignored scratch that CI writes and uploads.
